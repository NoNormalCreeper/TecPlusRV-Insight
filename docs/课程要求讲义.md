课程概述
课程性质： 本课程是计算机组成理论的实践延伸，要求学生利用HDL与EDA工具，从基础
CPU控制器出发，逐步设计并实现可支持小型操作系统与应用软件运行的完整计算机系统。在
AI大模型广泛应用的背景下，系统性能的瓶颈日益从算法层下移至硬件层，体现在计算效率、
存储带宽与资源利用率等方面。具备从需求分析到硬件落地的完整工程能力，是AI时代难以被
替代的核心竞争力。
核心目标： 以模型计算机系统及RISC-V等主流架构为参照，在资源与时序约束下，通过设计
指令集、数据通路与I/O接口，经历需求分析、方案设计、迭代调试、系统验证的完整工程闭
环，实现从单一部件到整机系统的认知跨越；在此基础上引入流水线技术，完成系统性能的量
化优化，建立软硬协同的系统级工程视角。
课程重点：团队分工与工程协作规范；工程项目迭代开发—从基础CPU控制器到完整计算机
系统的阶梯式推进，历经功能实现、时序收敛、资源优化、性能提升的多轮迭代；硬件约束下
复杂工程问题的定位、分析与解决；弥合软硬件认知断层，培养科研思维与工程实践能力；善
用开源实现与AI工具、具备工程审阅与系统整合能力，能清楚说明自己在系统中做出的判断与
贡献。
计算机系统设计——AI时代的工程师底色
从“实现CPU”到“理解AI芯片”：GPU、TPU、NPU的本质，是针对特定计算模式深度优
化的处理器架构。它们的数据通路设计、指令调度逻辑与存储层次结构，与本课程所实现的CPU
在架构原理上一脉相承。当你完成一个可运行的CPU设计，你所建立的不只是对模型机的理解，
而是读懂任何处理器架构的基础语言。
从“跑通指令”到“量化优化”：从AI时代的工程竞争力，不在于会调用多少API，而在于
能否理解系统性能从何而来、受制于何处。时钟频率、流水线吞吐量、访存延迟——这些指标在
本课程中都有直接对应的设计决策。学会在资源与时序约束下进行量化权衡，是从“会用工具”
迈向能“优化系统”的关键一步。
从“单人编码”到“系统工程”：大模型的广泛应用正在重塑软件开发方式，但也在放大
系统复杂度—更多的模块、更长的调用链、更难定位的性能瓶颈，也让“独立编写”与“审阅整
合他人/AI生成代码”同样成为核心工程能力。在本课程中，你将经历模块分工、接口对齐、联调
集成的完整团队工程流程。理解硬件行为边界、具备跨层次的系统调试能力，是构建可靠复杂系
统不可或缺的工程素养。

• 按照课程设计任务要求，选课同学按4人为一组分组，确定组长，建立小组内部沟通与讨

进阶层次—完整计算机系统设计
在基础CPU基础上集成内存与I/O接口，构建完整可运行系统：完成CPU、内存子系统（含Cache设计或
存储层次规划）与基本I/O接口的系统集成；能够支持小型测试程序的完整运行，分析系统性能瓶颈并提出
优化方案；引入流水线机制，对时钟频率、CPI与吞吐量进行量化评估。
拓展层次—高性能处理器优化设计
在完整系统基础上进行多维度性能优化与创新探索，从以下方向中选择至少一项深入实现：流水线冒险的
完整解决方案（数据前推、分支预测）；Cache替换策略优化与命中率分析；支持浮点运算或乘除法扩展
指令；基于RISC-V的自定义ISA扩展设计；面向AI/矩阵计算的自定义加速指令设计（如MAC乘加单元）;
进行多方案对比分析，在PPA（功耗·性能·面积）三角约束下给出设计权衡说明。

设计思路与技术要点
硬件描述语言（HDL）选择：VHDL或Verilog HDL
VHDL(DARPA美国国防高级计划研究局设计）
优点：强类型系统，数据类型严格减少错误；模块化设计，可读性高，代码结构清晰，便于维护和
理解。
缺点：语法复杂；应用领域市场占有率低。
适合设计需要强类型系统和多种仿真方法的开发。
Verilog HDL(Gateway Design Automation公司设计）
优点：语法简洁：；市场占有率高；灵活性高，适合硬件实现和电路的合成与优化。
缺点：弱类型系统，容易出现类型错误；模块化支持较弱；语法简洁，代码的可读性和维护性低。
适合更侧重于数字电路的行为模拟和硬件实现的开发。

Verilog工程应用技巧与规范
1.代码规范与可读性
使用清晰的命名规则：模块、信号、变量要有意义。
使用注释：特别是状态机、关键信号和复杂逻辑，增加代码可读性。
避免使用 assign连续赋值进行大规模组合逻辑，推荐always @(*) 来描述组合逻辑。
reg [7:0] data = 8'hFF; // initial 语句在综合中无效
2. 严格使用可综合语句
仅使用“always/`assign/if/case”等可综合语句； 避免“initial/fork￾join/time/force-release等仿真专用语句； 禁止在RTL代码中使用`#`延时（仅用于测
试激励）；不要使用循环语句。
always @(posedge clk or negedge reset_n) begin
if (!reset_n)
data <= 8'hFF; // 通过复位进行初始化
end

3.时序设计
所有寄存器时钟同步；
仅使用一个全局时钟（如 clk）驱动寄存器，
避免异步时钟域问题；
复位策略尽量使用异步复位同步释放；
采用非阻塞赋值 (<=) 更新寄存器；

reset_n) begin
if (!reset_n)
count <= 0;

2'b10: out = in2;

5.阻塞与非阻塞
阻塞赋值：语句按顺序执行，适用于组合逻辑建模。
非阻塞赋值：语句并行执行，适用于时序逻辑建模。
避免在同一个 always 块中混用阻塞和非阻塞赋值，以防止产生不可预期的行为。
6.建模选择
初学推荐行为级建模（模块+过程块描述）；熟练可使用数据流建模（连续赋值语
句assign+运算符）；慎用系统级建模（层级模块调用）

7.合理使用有限状态机（FSM）
使用 case 语句避免复杂 if-else 结构。
parameter IDLE = 2'b00, READ = 2'b01, WRITE = 2'b10;
reg [1:0] state;
always @(posedge clk or negedge reset_n) begin
if (!reset_n)
state <= IDLE;
else begin
case (state)
IDLE: if (start) state <= READ;
READ: if (done) state <= WRITE;
WRITE: if (finish) state <= IDLE;
default: state <= IDLE;
endcase
end
end
8.信号类型与操作符
建议仅用reg、wire型
数制尽量采用二进制
不做除法与取模运算
